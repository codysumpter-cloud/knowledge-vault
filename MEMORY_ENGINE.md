# KnowledgeVault Memory Engine

Status: active
Owner: Prismtek / Buddy ecosystem
Privacy: public
Last verified: 2026-06-09

## Purpose

The Memory Engine turns KnowledgeVault into a runnable local memory layer for humans, agents, and Obsidian.

It indexes markdown notes, extracts front matter, maps links/backlinks, searches records, exports context bundles, writes Obsidian-friendly indexes, and can run a local read-only HTTP API.

It is dependency-free by default. Python 3.11+ is enough.

## Quick start

From the vault root:

```bash
python3 -m memory_engine index
python3 -m memory_engine search "agent database"
python3 -m memory_engine show --query "cold start"
python3 -m memory_engine bundle --query "knowledge vault" --output "99-System/Context Bundles/adhoc.bundle.md"
python3 -m memory_engine obsidian
python3 -m memory_engine serve
```

After editable install:

```bash
python3 -m pip install -e .
kv-memory index
kv-memory search "agent database"
```

## Commands

### `index`

Builds JSON index files and an Obsidian index note.

```bash
python3 -m memory_engine index
```

Outputs:

- `99-System/Memory Engine/memory-index.json`
- `99-System/Memory Engine/memory-graph.json`
- `99-System/Memory Engine/Obsidian Memory Index.md`

Disable optional outputs:

```bash
python3 -m memory_engine index --graph "" --obsidian ""
```

### `search`

Searches title, path, tags, headings, summary, and metadata.

```bash
python3 -m memory_engine search "buddy-agent" --limit 5
python3 -m memory_engine search "runbook" --type runbook --json
python3 -m memory_engine search "memory" --tag agent-memory
```

### `show`

Prints a note by path or top search result.

```bash
python3 -m memory_engine show --path README.md
python3 -m memory_engine show --query "agent knowledge" --json --body
```

### `bundle`

Exports a context bundle from paths or search results.

```bash
python3 -m memory_engine bundle \
  --query "knowledge vault" \
  --title "KnowledgeVault Maintainer Bundle" \
  --purpose "Context for maintaining the vault" \
  --output "99-System/Context Bundles/knowledge-vault-maintainer.bundle.md" \
  --receipt "99-System/Context Bundles/knowledge-vault-maintainer.receipt.json"
```

You can also include exact files:

```bash
python3 -m memory_engine bundle \
  --path README.md \
  --path AGENTS.md \
  --path AGENT_KNOWLEDGE_INDEX.md \
  --output "99-System/Context Bundles/root-docs.bundle.md"
```

### `obsidian`

Writes an Obsidian-friendly generated index using wikilinks.

```bash
python3 -m memory_engine obsidian
```

Output:

```txt
99-System/Memory Engine/Obsidian Memory Index.md
```

Open the generated note in Obsidian to browse records by title, type, status, and tags.

### `new`

Creates a new note using the standard memory template.

```bash
python3 -m memory_engine new "30 - Projects/GitHub/codysumpter-cloud/example/Project.md" \
  --title "example" \
  --type project \
  --date 2026-06-09
```

### `serve`

Runs a local read-only API.

```bash
python3 -m memory_engine serve --host 127.0.0.1 --port 8765
```

Endpoints:

| Endpoint | Purpose |
|---|---|
| `/health` | Engine status and index stats. |
| `/search?q=term` | JSON search results. |
| `/record?path=README.md` | JSON record plus note body. |
| `/bundle?q=agent` | Ad hoc markdown context bundle. |

Example:

```bash
curl "http://127.0.0.1:8765/search?q=agent%20database"
```

## Obsidian integration

The engine integrates with Obsidian in four ways:

1. Reads normal markdown files and YAML-style front matter.
2. Extracts `[[wikilinks]]` and markdown links.
3. Generates an Obsidian-friendly memory index note.
4. Emits `obsidian://open` URIs for each indexed record.

Recommended Obsidian workflow:

1. Open KnowledgeVault as an Obsidian vault.
2. Run `python3 -m memory_engine index --obsidian`.
3. Open `99-System/Memory Engine/Obsidian Memory Index.md`.
4. Use that note as a generated navigation surface.

## Agent integration

Agents should use the engine like this:

1. Run or load `memory-index.json`.
2. Search for the smallest relevant task context.
3. Export a bundle for large tasks.
4. Verify volatile claims against live sources before acting.
5. Save receipts for meaningful work.

Example agent flow:

```bash
python3 -m memory_engine index
python3 -m memory_engine search "vault maintenance" --json
python3 -m memory_engine bundle --query "vault maintenance" --output /tmp/vault-maintenance.bundle.md
```

## Public/private behavior

By default, the engine excludes local-only and ignored-style private folders.

Use `--include-private` only for local private workflows. Do not use private-inclusive output for public commits.

## Files generated by the engine

Generated memory files live under:

```txt
99-System/Memory Engine/
```

These are safe to regenerate. Treat generated indexes as outputs, not hand-authored durable decisions.

## Design notes

This is intentionally a small local-first engine:

- no database server required
- no embeddings required
- no external API required
- no Obsidian plugin required
- JSON for agents
- markdown and wikilinks for humans
- HTTP for local app/agent integration

Future upgrades can add embeddings, SQLite/FTS, MCP, a desktop UI, or a real Obsidian plugin without replacing the current workflow.
